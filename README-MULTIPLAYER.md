# WildWastelandMP multiplayer and local testing

**RC12 / 0.1.48** requires **BepInEx 5 (Windows x64)** and the separate [Apocalypter Multiplayer mod from Nexus Mods](https://www.nexusmods.com/apocalypter/mods/10). Install both first, then extract the full WildWastelandMP release into `BepInEx\plugins`. Every player needs the same WildWastelandMP release, Multiplayer mod and compatible mod set. Keep standard WildWasteland disabled. See the [quick-start README](README.md) for the normal host/join flow; the three-instance launcher below is optional.

Save/load library (2026-10-19, **Testing**): offline and hosted SAVE GAME / LOAD GAME / F3 SAVES use a compact screenshot library with search, previews, independent save/world names, kilometres and MP-only saved-player counts. Manual saves, autosaves and backups have distinct tabs; autosaving never overwrites or prunes a manual snapshot. Delete, overwrite, restore and in-session offline load ask for confirmation. Offline uses the same journaled snapshot/backup/rollback manager; new worlds have independent identities. SYSTEM contains saving/backup/cleanup settings and the existing Debug toggle. New cleanup is off by default; existing Patrols cleanup is shown separately. Standalone Apocasaver is suppressed; Apocasetter is unchanged. See [save safety and required runtime checks](compat/ApocalypterMP/HOST-SAVES.md). This supersedes older current-slot-only save descriptions below.

Build from Windows PowerShell:

Current sleeping-player/respawn build is Testing. Disconnect leaves a camera-facing `Name - Sleeping` ragdoll; look at it and use LMB with empty hands (or Use) to carry/drop it. The body persists throughout joining until confirmed spawn; markers follow it and notices change from is connecting to has connected only after host confirmation. Rejoin returns the player beside its latest moved position with the latest host-validated inventory/stats, keeping the separately selected respawn point. Holding F still sleeps normally; Secondary Use (`Use_2`, normally E) selects the exact bed, bedroll or seat as the player's one respawn anchor. That object and its attached vehicle remain protected from cleanup even while the owner is offline. Downed players have no revive deadline; explicit Give Up respawns beside the selected object's current position on a clear supported surface, otherwise beside the host for guests (initial camp for the host). World reloads still restore the matching world/player snapshot. See [sleepers and respawn tests](compat/ApocalypterMP/SLEEPERS-RESPAWN.md).

```powershell
dotnet build WildWastelandMP.csproj -c Release -p:Deploy=true
```

The DLL deploys to `E:\SteamLibrary\steamapps\common\Apocalypter\BepInEx\plugins\WildWastelandMP\WildWastelandMP.dll`. Close both copies before rebuilding/deploying. Assets live beside that DLL. ApocalypterMP.dll remains a separate dependency.

Double-click `Start-WildWastelandMP.bat` in the repo or the game folder. It opens three visible copies at the title menu: HOST, CLIENT and CLIENT2. It does not load a world, host or join automatically, or run automated gameplay tests. Optional arguments: `host`, `client` or `client2` to launch only that role; `both` retains the original host/one-client launch.

The host uses the main game executable. Guests use `MP\Client` and `MP\Client2` inside the game folder, sharing the installed plugins/data through directory junctions, with separate BepInEx settings and player identities. Launcher saves/settings.xml live in `MP\Saves\host`, `MP\Saves\client` and `MP\Saves\client2`; launcher Player logs are `MP\Logs\host.log`, `client.log` and `client2.log`. Choose the world in HOST setup, then JOIN from both clients. An existing first-launch `WWMP_Local.es3` and its player registry copy forward to `MP_WWMP-Local.es3` when the canonical save is absent; originals stay intact.

Direct launches can report SteamAPI initialization failure. This BAT uses UDP at `127.0.0.1:27861`, independently of Steam. Normal menu/Steam sessions keep their ordinary identity/path behavior.

The title and ESC menus have MULTIPLAYER; click it to open the panel to the right. HOST (STEAM) or HOST (IP) opens setup for WORLD NAME and the existing cars, foot-patrol, POI/weather and map/compass world settings. At the title menu, choose an existing save or a new world with a seed. Existing saves are loaded in place; ESC hosting uses the current save. Host Save writes to that selected world slot. Client Save sends the host a message such as `Alex wants to save`; it does not save automatically. F3 has separate PLAYER, WORLD and HUD navigation pages.

On the other copy, use MULTIPLAYER > JOIN at the title menu with the host's IPv4 address and matching UDP port; the local BAT defaults to 127.0.0.1:27861. Both copies require handshake revision 24 and identical loaded mod versions/builds (RC4). Click an address/port row and type to replace it, Enter to apply or Escape to cancel. X/Escape closes the panel; Escape during endpoint editing only cancels that edit. JOIN from ESC offers to return to the title menu first; save beforehand, then click JOIN there. DISCONNECT stops hosting or cancels joining; a connected guest returns to the title menu. F5–F8 no longer control multiplayer; F9–F12 MP debug actions remain blocked. These controls use Clean menus (enabled by default). Local menus/F3/inventory do not pause an MP world; the shared save transaction still freezes gameplay while writing.

PLAYER offers eight portrait-only model choices in one row, with Female/Gungirl/Shoota together; TAB uses the selected model's portrait too. Duplicate Mechanic/Pistoleer choices map to Merchant/Bodyguard for legacy configs. HUD has separate local Floating names, Players on compass and Players on map switches, including a colored self arrow on the map. Automatic update checks are suppressed for now. RC4 built/staged DLL MD5: `14499795E93C67EC859202B9573E47DD`. Local RC3 has a removal queued in Apocasetter; that operation was preserved and RC4 was not deployed over it. Gameplay remains Testing. See [character and TAB tests](compat/ApocalypterMP/CHARACTER-BODIES.md) and [player HUD/mod matching tests](compat/ApocalypterMP/PLAYER-HUD-AND-MOD-CHECK.md).

Player recovery (Testing): every five minutes, the host writes a small player checkpoint without starting a world save or pausing gameplay. It covers native carried weapons/gear, ammo, health and armor; clean client exits send a final report. An unclean reconnect to the still-running host recovers the latest validated player record and displays a top-left CleanHUD notice. Every full world save embeds all known players, including those who left. **Every world reload restores everyone to that save's player snapshot**, discarding newer checkpoints even after a host crash. Existing worlds need one full save with this build to establish rollback protection. Details, storage paths and manual tests: [PLAYER-RECOVERY.md](compat/ApocalypterMP/PLAYER-RECOVERY.md).

Optional mod recommendations are hidden by default. Enable them through Wild Wasteland settings > Debug > Core > Switches > Recommended mods (Enable Debug must be on). This adds settings.cfg `[Debug] Recommended mods = false`; it does not change multiplayer endpoint settings.

The MULTIPLAYER panel has a NAME field for your player display name (1-48 characters). Click it and type, then Enter to save or Escape to cancel; HOST/JOIN also apply it. Change it before connecting. The name persists in settings.cfg `[Multiplayer] Name`; an empty config entry retains native Steam/launcher naming. This changes display names, including chat and save requests, while preserving player/save identity.

The public mod/assembly is named WildWastelandMP. RC4 uses its own plugin GUID, com.denis.apocalypter.wildwastelandmp. Existing namespaces and configuration/save keys remain for compatibility; do not load base WildWasteland alongside this build.
