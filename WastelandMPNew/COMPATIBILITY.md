# Multiplayer behavior and optional-mod compatibility

Consolidated 2026-10-22. **Testing/source evidence does not mean verified gameplay.** The current WWMP implementation is the behavioral reference; the new kernel implements only the mechanisms listed in [IMPLEMENTATION-STATUS.md](IMPLEMENTATION-STATUS.md). Full reports, test steps and subsequent corrections are frozen under [reference/](REFERENCE-INDEX.md).

## Authority and lifecycle rules

| Concern | Required behavior | Existing evidence / WW2 destination |
|---|---|---|
| World execution | Host owns AI, natural spawns, patrol journeys, encounters, storms, world quest state and reputation. A host menu must not pause simulation needed by active guests. Local presentation/input remains per player. | `Core/MultiplayerWorld.cs`, `GameRefs.WorldRunning`; NPCAI, Patrols, POI, Survival and Quests via Core session query |
| Admission | Exact gameplay mod/schema/content match before world launch. Guest receives generation policy before `setSeed`. Admit transport, settings, object snapshot, inventory restore and placement as separate stages. | `MultiplayerHandshake`, `MultiplayerModManifest`, `MultiplayerJoin`; Core + MP adapter |
| Local settings | Display switches, body/camera, local volume, debug and identity remain local. World/AI/map-discovery policy belongs to host. Session overrides must never serialize into guest preferences. | `MultiplayerSettings`; explicit new-key schema, not old module-name heuristics |
| Entity identity | Host assigns runtime ids and binds saved ids into guest snapshots. Never infer identity from display names, `MP_` physical names, instance ids, hierarchy order or a local counter. | `MultiplayerItems`, `MultiplayerActors`, respawn mapping; Core `Entities` |
| Coordinates | Positions retained/sent over time use Core world coordinates; convert only at rendering/physics boundaries. Origin shifts are local events. Terrain probes use the same world frame. | `Origin`, `TrafficSpace`, Vistas terrain probe; Core `Origin` and `WorldTiles` |
| Ownership | One simulator per mutable object. All forces, resource writes, fitted-part changes, collectors and physics agree with host-assigned ownership revision. Driver/seat and item-owner handoffs need arbitration. | `MultiplayerItems`, `MultiplayerParts`, `MultiplayerVehicles`, `MultiplayerSeats`; Vehicles/Core |
| Joins | Capacity-aware catalogue/chunk send, complete generation hash, final receipt and **actual apply/placement proof**. Incomplete inventory restoration does not count as readiness. | `MultiplayerJoin`, `MultiplayerSnapshot`, `MultiplayerSleepers.Wake`; MP coordinator |
| Leave | Revoke admission first; remove reliable state, transfers, avatars, poses, markers, cached choices and ownership. Ignore delayed packets. Keep latest confirmed player checkpoint; do not force full world save on guest departure. | `MultiplayerPlayers`, `MultiplayerRecovery`, `MultiplayerPerf`; session-owned cleanup |
| Security | Bind sender from transport; validate direction, epoch, target, ownership, finite bounds, reach and rate before native side effects. Rejected deltas cannot undo already granted ammo/money/health. | `MultiplayerEdits`, `MultiplayerItems.Resources`, transactions; domain request/result codecs |

## Gameplay domains to carry forward

| Domain | Semantics and pitfalls | Main existing sources / reports |
|---|---|---|
| Saving | Freeze ready owners only; owner item/car reports and then player poses must be applied before acknowledgement. One 30s total owner/optional-work budget; timeout saves last confirmed host state with yellow diagnostics and retains pending queues. Terrain, authoritative commit and file-integrity failures still block publication. First write failure remains latched after a later successful callback. | `MultiplayerSaving`, host-save framework; [save timeout](reference/wwmp/notes/save-sync-timeout-2026-10-21.md), [HOST-SAVES](reference/wwmp/compat/ApocalypterMP/HOST-SAVES.md) |
| Save identity | Host selects a real save identity separately from display name. Pin selection before entering scene; native `setSeed` can run before `LoadGame`. Named manual/auto/backup snapshots include all known players and companions. Restore the selected world generation's embedded player state; never overlay a newer checkpoint onto an older world. | `MultiplayerHosting`, `SinglePlayerSaving`, `MultiplayerRecoveryStorage`; [SP selection](reference/wwmp/notes/sp-load-selection-2026-10-21.md) |
| Vehicle save poses | Last accepted owner car snapshot is authoritative. Generic tracked spawn/claim pose can be stale; freezing it can teleport the car and seated observers back. Final car relay precedes passenger reports. Restore standing clearance beside parked cars when required by native load behavior. | `MultiplayerSaving`, `MultiplayerVehicles`; HOST-SAVES vehicle sections |
| Resource transactions | Grant before credit. Scope to exact FSM/use operation, owner revision and participant; dedupe retries. Ammo/battery/nuts/food/drink covered in current overlay; arbitrary mods and pouring/refilling are still gaps. Expired/abandoned leases release while retaining host amount; actual failed host commit fences saving until a verified reload. | `MultiplayerItems.Resources`, `MultiplayerTransactions`; [assessment, final corrections](reference/wwmp/notes/multiplayer-assessment-fixes-2026-10-20.md) |
| Inventory/equipment | Exact saved slots, loaded ammo, ownership and pending adoption must settle before sleeper wake. Death clears old recorded inventory so dropped objects are not recreated on rejoin. Keep native saved item names and stable ids within the chosen WW2 format. | `MultiplayerInventory`, `MultiplayerPlayerReset`, `MultiplayerItems.Lifecycle`; INVENTORY-PLAYERS, AMMO-COUNT, DROPPED-GUNS |
| Sleepers/reconnect | Host-only ragdoll physics; eleven bodies with only hips pinned during carry, main-terrain support/clearance checks before gravity. Moving body changes reconnect placement, never selected respawn anchor. Offer/ready/grant/placed/cancel uses attempt token; retain body/inventory until full restore and host-confirmed final pose. Disconnect/host crash reconstruction follows the loaded snapshot. | `MultiplayerSleepers*`, `PlayerBody/SleepingBodies`; [SLEEPERS-RESPAWN](reference/wwmp/compat/ApocalypterMP/SLEEPERS-RESPAWN.md) |
| Respawn/revive | One explicit bed/bedroll/seat anchor per identity; preserve object and parent car against cleanup/virtualization. Fall back to camp if anchor unavailable, not arbitrary host position. Revive has no deadline with native downing enabled. Downed crawl retains focus/chat/editor/freeze guards. | `MultiplayerRespawn`, `MultiplayerCombat`, `MultiplayerPlayerReset`; SLEEPERS-RESPAWN |
| Combat | Host verifies world outcomes; separate ordered combat from bulk joins. Damage, revive and restore ordering must agree. Guest creature melee uses local reach confirmation and native bodypart/hurt effects. Requests/intents differ from committed hurt results. Validate each target's cave/darkness/hearing context. | `MultiplayerCombat*`, Gunplay networks, NPC `VanillaEvents`; [client melee](reference/wwmp/notes/client-side-melee-2026-10-20.md) |
| Vehicle occupants | Animal/human melee only when seated car is stationary **and** engine off; still <=0.1m/s and <=0.1rad/s. Unknown seated state protects. Use owner snapshots for remote kinematic cars. Guns/explosions/on-foot targets retain their own rules. Own-car collision protection differs from NPC ram validation. | `VehicleMeleeProtection`, `MultiplayerCombat.Cars`; vehicle-melee-policy and occupant-collision reports |
| Dog reach | Never call `ClosestPoint` on an inactive/disabled collider: it can return the query origin and falsely report 0m range. Fallback to target position. This does not prove/fix the apparent on-foot one-shot or backward downing incident. | `DogAnimations`, `DogBite`; dog-seated-reach and dog-on-foot-damage audit |
| Projectiles/ammo | Keep authoritative hit separate from visuals. Crossbow base player damage is 2.5x native 20 = 50 before falloff; tooltip handles optional `MP_`. Crossbow launch/attachment/impact ordering needs reliable state/tombstones, while ordinary cosmetic impacts can drop. Magazines need exact inventory/save state. | Guns `NetworkShots`, `NetworkImpacts`, `NetworkBolts`, `NetworkMagazines`; special-combat/ammo reports |
| Vehicle parts/seats | Doors/fitting/hinges/wheel damage/fluids/handbrake/ignition/cassette need domain replication beyond transforms. Passenger request is host-arbitrated; do not grant a seat from independent local raycasts. Remote telemetry comes from owner snapshot, not observer rigidbody. | `MultiplayerParts`, `MultiplayerVehicles`, `MultiplayerSeats`; PART-STATE-CHECKLIST, ISSUE-1-PASSENGER, MOTORCYCLE-OWNERSHIP |
| Patrols/traffic | Host creates and virtualizes journeys. Guests mirror actors, templates, fixtures and appearance. Keep cars anchored/protected for offline players and explicit respawn anchors. Build cache consumes dormant preprocessed instances instead of cloning away preparation. Source activation can still cause spikes. | Patrols `TrafficNetwork`, `MultiplayerPresentation`, world/cleanup protections |
| Merchants | Initialize stock prices before registration. Paid purchase and hostility zero-sale are distinct. Restore tracked untaken hostility-released stock price after recovery; taken/paid stock stays released. Reconcile cached state every 3s. First-ever physical bus spawn alone has empty-cargo/physics-area extra-item audit; revisit restores cargo without deletion. Exclude exact separately restored trader stock from new cargo snapshots; retain legacy ambiguous cargo. | Patrols `MerchantHost`, `NetworkMerchants`, persistence; [stock reconciliation](reference/wwmp/notes/merchant-stock-reconciliation-2026-10-21.md), purchased-items-sync |
| Purchase interaction | Copying `ForBuyInt=0` alone is insufficient. Reconcile the native Buyable interaction transition, or host/other guests retain BUY while local buyer sees usable item. Never replay payment during mirror apply. | `MultiplayerItems.Edit`; purchased-items-sync |
| Nests/animals | Host builds webs, alarms, pounce/burrow logic; guests get exact bounded mesh and bone-pose streams. Consider guests when choosing activation/hazard range. Late join requests missing mesh; guests retain local lighting only. | NPC nests/web/pose network, GUEST-WORLD-SYSTEMS |
| Storms/shelter | Host tracks native weather anchors near all players (up to native 64); each camera renders nearest four. Host hazard checks resolve remote player shelter/car state. War Rig shelter covers guests. Native encounter identities/save lists remain authoritative. | Weather network/hazards, Patrols shelter; GUEST-WORLD-SYSTEMS |
| Quests/party | Host owns quest book, reputation and progress; guests send conversation/hire intents with nonce/sequence. Shared quest payout goes in full to each connected player's **separate wallet**. Preserve leader/follower identity, crew exclusions and empty delivery recovery. | `MultiplayerParty`, Quests `PartyQuests`, `PartyInteractions`; quest source inventory |
| Fog/discovery | Host world policy plus shared exploration/known locations; local map/compass/name-tag display switches remain per player. Bounded changed chunks/snapshots; no full-map rebuild on every paint. Save-and-exit must write at the actual save serialization phase, since return to isPlay may never happen. Atomic replacement for fog and location files. | `MapFog.Network`, `LocationMarkers.Network`, MultiplayerSnapshot; SHARED-FOG |
| Presentation | Speaker's identity chooses voice/model, never listener's gender. Remote motion/equipment/model choices share synchronized identity; clear caches on departure. Render-only clones must not enter save/item lists. Camera billboarding uses actual rendered camera matrix for third person. | PlayerBody multiplayer files, `MultiplayerNames`; CHARACTER-BODIES, POSES-EQUIPMENT, speaker-shout-gender |
| Menus/notifications | Hosting waits for selected world; joining from live world returns through title. Guests request a save by identity/name; request never automatically executes one. Input blocks during chat/settings/save/load. Client UI retains local controls while world settings lock. Save warning 0 skips countdown and extra delay. | MultiplayerHosting/notifications, HUD, HOSTING-SETTINGS, HOST-SAVES |
| Optimizations | Reuse Core world/FSM/prefab/player queries. No duplicate per-module scans or uncontrolled reflection. Simulation-changing culling/sleep/time features must never simulate on guests. WWMP currently disables Performance broadly; WW2 needs explicit certified host/local policies, not blindly copying either switch behavior. | `MultiplayerPerf`, refactor Core Optimization/Debug |

## Optional mods

All third-party discovery/signature resolution belongs to **Compatibility**, never this kernel or another module. A newer version warns and attempts signature resolution; unsupported APIs produce a named capability failure. Missing required gameplay capability rejects admission before generation. No optional mod DLL/source/assets are redistributed here.

| Mod | Current known behavior | Required WW2 MP adapter / limits |
|---|---|---|

Per-machine SpawnTrack and dust devils forced off. Guests follow public `a.z` weather API; host unscaled clock synchronizes wind/gust functions. Owner-only forces/dew/heat; AI-held and never-entered patrol cars excluded from heat. Terrain probes check consistency. | See detailed section below. ## Vistas details that must survive the rebuild

The [full Vistas MP report](reference/wwmp/notes/vistas-mp-compat-2026-10-22.md) lists exact current keys and signature evidence; [the earlier overlap audit](reference/wwmp/notes/compat-VistasWorldGen.md) covers routing/render/heat interactions. Obfuscated names below are evidence of the inspected build, not contracts to hard-code in the new kernel.

1. Host keys: all `Terrain`; Regions Enabled/Scale/Blend/ExtraTypes/Landmarks; Roads Network/Density/Width/Stitch/Clean; Tiles.WeldBoost; Seams.CrossDetail; World ElevationTiers/TierStrength; Water.AltitudeDew; Vehicles EngineHeat/LooseSlopes/RoadLayers/RoadBoost/HillAssist; Weather Enabled/Gameplay/GameplayStrength/Haboob/Thunderstorms/Aurora/MeteorShower/Nebula. Camera/fog/audio/tint/banner/debug/weather visuals remain local. Lock generation keys for the entire session. No cache key based on the guest's original serialized setting: use effective values.
2. `Roads.SpawnTrack` is generated from the local first position to locally loaded places and regrades terrain. A shared seed cannot make it identical. Force it off for every peer, restore local preference on exit. An SP-generated strip may revert in MP. Dust devils spawn from local camera/TickCount and push bodies; also off until host replication exists.
3. Guest weather follows source public `a.z`: running `a()`, follow `A(bool)`, snapshot `B()`, apply `A(byte[])`. Reassert follow after source reset. Current bridge uses roughly 1s snapshot refresh, 0.5s follow check, clock offset for `a.g.A(float,int)` and `a.H.g(float)` wind/gust inputs. Reject non-finite/backward host timestamps and bind offset to world epoch in the new bridge. WW owns dust/haboob while MP session weather is active; visual lightning/meteors can remain local if they never mutate gameplay.
4. Heat ignores crew-locked/unentered patrol cars and remotely owned cars; remove stale source power modifiers/readout when ownership changes. Wind/hill-assist/devil forces and collector Liquid/Capacity writes run only on owner. Use Core ownership, not observer `isKinematic` alone. Resolve the EngineSim heat/ignition ownership explicitly.
5. Roads: capture the actual ordered centreline registration and final grading, never join unordered hints. Final terrain snapshots and fog rows use 500us slices. Vehicle routes reject unknown ground, grades above 22% for trucks/convoys or 30% for cars, and unsafe 6m corridors/footprints; foot solver is separate. Clear captured roads on source network reset; invalidate regenerative cache with effective generation/DLL identity.
6. MapMagic products disappear after Finalized: capture immutable generation data there, consume on Applied. New Core WorldTiles supplies the one subscription/handoff. Vistas grading invalidates terrain/nav/road samples. A 10s 7x7/25m full-detail terrain probe is diagnostic sampling, **not proof of equality everywhere**; repeated mismatches warn and should block readiness when the required local patch differs.
7. Vistas uses repeated obfuscated field names differentiated by type. Existing MonoMod operand-resolution repair matches assembly + declaring type + name + resolved field type. Compatibility owns any narrowly scoped runtime repair; do not reintroduce global name-only reflection or `Reflection.Emit` hot paths.
8. Vistas far clip/tile material/detail can compete with Core Optimization; use property ownership/CameraArbiter. Banners/scouting must have one owner. Vistas external jobs/forces cost time outside WW scheduler measurements; profile them explicitly.
