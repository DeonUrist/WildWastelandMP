# Automatic standalone replacement (Testing)

Requested by Denis on 2026-10-16: disable replaced mods via Apocasetter, show a main-menu restart notice with the names/count and a warning that the standalone mods should be removed from the active mod set.

Cause: ModuleHost's conflict check only left WW modules OffConflict. Feature-level guards also yielded HealthStacks, iTweenGuard, female NPCs and map fog to the loaded standalone. Nothing queued removal from the active plugin set.

Implementation: Core/ReplacementGuard.cs gathers the registered ConflictsWith GUIDs plus local.immersivemap, WomenOfWasteland, HealthStacks and iTweenGuard. Core/ApocasetterBridge.cs uses reflection on the existing Catalog.Find, ModEntry.PluginPaths, Updates.OpFor/Stage and MiniJson.Parse APIs. The queue uses op=disable, removeConfig=false and preserves an existing disable/remove operation. Its persisted pending.json operation is checked because Updates.Stage catches write failures internally. Shared directories fall back to the plugin DLL; shared DLLs and paths outside plugins are refused. Compatibility dependencies (Talk, Quests, Engine Sim, ChaseCamera, Apocaspawner, Apocapocket, etc.) are not replacements and are not disabled.

Plugin.cs adds Immersive Map's soft dependency and runs Prepare before built-in fix/module startup. Scene callbacks update title visibility; the initial title check is deferred to a scheduler interval, avoiding scene access in Awake. The notice uses existing Core UI skin, cached content and a field-only GUI predicate; no GUI job exists without a conflict, and it is hidden in the world and while MODS/settings are open. The Modules page and feature-level messages explain the queued restart. The original guards prevent duplicates for the remainder of the current process. Config switches remain unchanged.

Native source evidence: Apocasetter/SettingsUI.cs StageSimple passes PluginPaths and removeConfig=false to Updates.Stage; Updates.cs Stage/SavePending persists pending.json; Installer/Installer.cs MoveAway moves plugin files into cache/Apocasetter/disabled/GUID and records manifest.json before the next chainload. Apocaplayer, Apocapatrol, npcai, Gunplay, GunplayHUD, WomenOfWasteland and StewPot source entry points establish independent persistent runners/scene callbacks; disabling their BepInEx component would not stop their gameplay.

Denis's test:
1. Start with WW, Apocasetter plus its installer, and a replaced standalone (Stew Pot is already installed). Do not start gameplay yet. The title menu must show RESTART REQUIRED with the count/name and the standalone-removal warning; MODS should show the disable queued. Log: `[Core] Replacing Stew Pot: disable queued in Apocasetter; restart the game for Wild Wasteland to take over`. Survival stays off during this first process to prevent duplication.
2. Quit normally and restart. Apocasetter's installer moves Stew Pot to its disabled cache, its cfg stays in config, the notice disappears, and `[Survival] started` replaces the previous conflict. Test its normal gameplay. Other replaced mods follow the same path; Immersive Map/Women/HealthStacks use their existing feature-level WW implementations.
3. Verify that Talk, Quests, Engine Sim, ChaseCamera and other optional compatibility mods still load. Check both an installed dedicated plugin folder and a loose standalone DLL if available; unrelated plugin files must remain active. An unavailable installer produces a manual-disable label rather than claiming success.
4. No runtime/game/UI testing or profiling was performed by the agent. Verification is the Windows Release build/deploy only. No config entries or external DLLs were changed by the development session; disable operations are queued when Denis next starts the game.
