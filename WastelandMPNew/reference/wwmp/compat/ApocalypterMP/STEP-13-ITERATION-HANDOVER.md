## What the eight batches changed

1. **Server save barrier:** only the host initiates world serialization. The host freezes gameplay, requests ordered owner state/player flushes, drains queued part edits, waits for connected peers, then uses MP's original world save. Everyone shows SAVING; transport/Core/presentation stay alive. Disconnect cleanup removes departed peers from the wait. Slow peers do not trigger an incomplete speculative save. Final part snapshot barriers are included in the pending check.
2. **Interactions and Engine Sim:** nearby numeric repair/refill mutations route through the host to the current item owner as deltas. Native variable baselines converge. Custom pots cook/spoil/spill on their simulation owner, with native ownership requested before drinking/adding meat/receiving a pour. Engine Sim DriveCoupling and WheelCoupling yield on remote-owned vehicles; native worker/audio implementation and post-physics timing remain original.
3. **Join/settings:** matching WW handshake revision is required; host world settings are compressed, bounded, validated and applied before accepting native WorldInfo. Initial Hello retries and ordered bootstrap delivery cover supplied UDP's ignored reliable flag. Failed bridge installation stops/blocks MP entry instead of silently starting independent WW simulation.
4. **Special combat:** host transient monster orbs, rider lances and explosion visuals have inert guest presentation copies. Rider kamikaze damage checks every remote player and their car hull. SanityAdd reaches the guest's native FSM. Range/amount/targetable checks reject invalid creature damage requests. Native ranged part damage works beyond four metres when Guns is off.
5. **Player/items:** per-item magazine fields extend MP ItemVars and SavedItem.Vars; weapon draw imports the physical item's rounds/hammer. Host saves import them into the unchanged Apocaunloader.Magazines ledger for offline compatibility. The current magazine is captured before save flush while gameplay is paused. Six extra native character choices are available with or without MP and use WW player animations.
6. **World lifecycle:** host hurricane forces route to the actual player/item/car owner; rider vehicle impulses deduplicate shared occupants. Follower health observation follows the chosen player with cache reset on owner change. Late actor identity announcements repair post-spawn appearance changes. Only map presentation routes sample at most 512 points; host travel simulation routes remain intact.
7. **Permissions/UI:** guests retain HUD display preferences plus map/compass on/off; host owns world/fog/obfuscation/marker policy. Debug/Developer/Performance access stays host-only, Performance itself remains off for everyone in MP. Both CleanHUD and native guest Save buttons are disabled/gray. A Core full-screen SAVING fallback covers unavailable CleanHUD. Settings/input buttons are blocked during server saving. Guest weather installs the Azure fog presentation scope.
8. **Final source review:** fixed reflected FindPrefab's actual two-argument signature; detected host-world activation even when transport mode does not change; fresh guests now accept payout receipts; death reports preserve receipts applied just before death. Quest resync requests include session and fully applied version. Guest camp-cleared state comes from host traffic snapshots. Native explosion force uses one shared Core dispatcher with Weather, preserving its Tornado interception. Guest thrown explosives relinquish their gameplay copy after native launch reporting; the host creates the gameplay projectile and sends presentation.

## Known limitations / next source work

- **Do not claim ALL WW features fully synchronized yet.** Exact weapon/ammo/trajectory validation remains incomplete; current creature hit validation checks identity, state, distance and bounded damage, not an authoritative reconstruction of every shot. The Guns-disabled ranged fallback is a permissive bound, not weapon-derived reach.
- Crossbow landing/embedding/corpse attachment still relies on per-peer visual collision timing. An authoritative hit/attachment correction stream is not implemented. Repeated transient descriptors lack removal tombstones; a delayed unreliable descriptor can briefly recreate a removed effect until expiry. Fast effects can end before the next descriptor tick.
- Native numeric edit routing covers discovered float/int fields. String/bool/native fitting/consumption interactions, concurrent repair/wear/refill conflicts, rejection resource refund and ownership change mid-operation still need a complete transaction audit. No claim that blast-lance/armor/door/trunk behavior has passed the live/save/offline matrix.
- Custom pot ownership acquisition is native optimistic claiming, not an atomic two-pot/ingredient transaction. Competing cooks/drinkers/pour targets and owner handoff need further review. Boiling/pouring presentation is not fully replicated.
- Engine Sim optional API behavior, remote session lifecycle/torque/audio and tuning access remain unverified. The integration does not redesign the external simulation threads.
- Save pause/barrier has not run in game. Native owner transform/car interpolation, queued native events, mid-save disconnect/quit, exception/abort cleanup, save-and-quit sidecars and restoring physics/temporary component state while scaled time is zero require careful review/test. No partial-save timeout fallback was added. A stalled connected peer can hold the barrier.
- Receipt counters are cumulative and travel in native stats; death/fresh-guest ordering was repaired, but full late restore/report/downed/reconnect/capacity ordering still needs manual validation. Character preference remains local config; per-world character persistence is not a new save system.
- Camp/actor/world snapshots, fog/discovery sidecars and native list ownership need reconnect/world-switch/save-and-quit review. Travelling foot patrols remain journey-owned and native registration must not duplicate their save owner. Modded prefab/layout compatibility is not established.
- Handshake/delivery is source-reviewed against the supplied MP protocol21 DLL only. All peers need this same final overlay. Optional reflection/Harmony runtime installation is not proven by C# compilation; no headless or Steam/UDP connection has been run.
