# Wild Wasteland MP RC14 (0.1.50) — Multiplayer reliability and combat

- **Guest melee and feedback:** creature melee reach is checked on the affected guest, with hurt sound, flash and camera effects restored. Hostile dogs use native attack timing in multiplayer. Damage, revive and restoration use a separate ordered combat lane so world transfers do not hold them up. Melee packet IDs no longer overlap sleeping-body packets.
- **Joining and transport:** paced object streaming waits for its final acknowledgment; snapshot hashes avoid redundant transfers, large handshakes/settings are chunked, socket failures are contained, and queue exhaustion fails the affected connection explicitly. Departed peers cannot recreate stale avatars through delayed packets.
- **Saving and recovery:** loading peers stay out of owner-freeze barriers, autosaves wait for joining/placement with bounded grace, and reports precede their acknowledgments. Death clears stale recorded inventory; downed guests retain the revive-health policy. Placement/restoration has bounded failure paths and respawn follows the current selected anchor. Verified file copies perform fewer reads and the host transaction flushes the world once after module writers.
- **Shared items and vehicles:** native ammo, battery, nuts, food and drinking interactions reserve the item before player credit. Timed-out or abandoned reservations release with the host value retained; a failed host commit blocks saving and offers return without saving. The host arbitrates passenger seats. Item deletion/adoption, replica metadata, queued part damage, guest ram geometry, boss scaling and per-target cave checks are corrected.
- **Traffic and native caches:** motion relays avoid echoing to their sender; appearance, party and transaction updates repeat less often. Moving effects use compact poses and most impact visuals use unreliable delivery. Native object lookups and caches are reused/pruned; malformed-packet logs are limited per peer. Chat/editor input guards cover camera and cockpit controls. Performance still needs measurement in game.

Every player must update and restart: **handshake 27** requires matching WWMP and loaded mod builds. Required dependencies remain separately installed **BepInEx 5 x64** and [Apocalypter Multiplayer 0.4.1](https://www.nexusmods.com/apocalypter/mods/10). Extract the full ZIP into `BepInEx/plugins`, keeping standard Wild Wasteland disabled. Optional Ultimate Tools synchronization and embedded world-save data from RC13 remain included; install the same Ultimate Tools build separately on all peers when used.

**Non-Steam identity change:** a generated `[Multiplayer] Install identity` in the top-level plugin config now distinguishes installations with the same Windows username. It stays local and is not host-synchronized; do not copy it between PCs. Steam identity is unchanged. Existing username-keyed UDP player records remain in the save but are not automatically claimed, so a returning UDP player can receive a new record. This is collision avoidance, not peer authentication.

Gameplay, synchronization, save integrity, visuals and performance remain **Testing**. The reported on-foot one-shot and backward downing placement still require reproduction; these changes do not establish those incidents' causes. Shared-item reservations cover the native events listed above, not pouring/refilling or arbitrary third-party resource operations; abandoned-result handling does not establish generic duplication protection. Other native performance/security findings remain open.

Manual checks with a host and two guests:

1. Join a populated world and wake a sleeping guest while autosave is due; complete placement, save, reload and reconnect. Confirm inventory, dropped items, health, respawn anchor and sleeping bodies agree.
2. On a guest, take a dog bite, sprint out of reach and take a ranged hit. Expect hurt feedback on accepted hits and `Melee N ... hit/dodged` log lines; a single dog's bites should follow native timing.
3. Use the same ammo/food/drink from two peers, including disconnect/save boundaries; check both inventories and the host item quantity. Race two guests for one passenger seat.
4. Exercise guest-to-guest drops, part damage, cave effects, chat input and Ultimate Tools edits; compare traffic/frame timing during long sessions and interrupted UDP delivery.
