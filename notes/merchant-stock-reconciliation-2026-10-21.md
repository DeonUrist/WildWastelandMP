## Final behavior

- The merchant sale-state fallback runs every three seconds using cached root FSM references. Existing purchase/event synchronization remains. Host purchase records are retained after removal from the shelf; periodic reconciliation releases stale Buyable/ItemName interactions for paid stock on host and guests. Unpaid stock follows the existing host Trading relation. A friendly guest's zero flag may be an unconfirmed local purchase: the guest does not turn that zero back into a sale independently; the host's reliable native flag update owns restoration. This avoids undoing payment while its host confirmation is in flight.
- The existing merchant snapshot carries the current native object ID for exact guest item lookup, with no scene/name search or new packet kind. IDs are cleared/recomputed before every capture, including records not bound after restore. The optional hostilityReleased flag and objectId use the existing MerchantSave JSON, with old missing fields defaulting false/zero. No config, top-level save key, version or handshake changes. Old purchased records cannot be reclassified as historical hostility releases safely.
- New stock is registered only after price/sale initialization, closing the explicit pre-initialization publication gap. Existing price values, including historical zero prices, are not retuned by this task.
- Coyote_Trader's embedded template uses car-empty. Parsing that exact template also enforces car-empty for older disk copies without rewriting live files. First merchant builds and direct fresh Coyote_Trader builds skip ordinary car and trailer cargo loads; restored physical traffic vehicles retain their saved cargo.
- MerchantSpawnAudit runs only for the first actual vehicle instance produced by VehicleBuildCache.Spawn, not warm/cache templates, later rematerializations or subsequent periodic updates. The existing serial BuildQueue assembly owns reused buffers. Before activation, the audit snapshots registered existing items and objects already overlapping the bus's PhysicsLock BoxCollider. Existing fitted parts are explicitly allowed. After the existing one-second spawn-settling wait, before publication, it performs one bounded overlap of that same oriented box. Newly appeared ES3 items with ForBuy, whose pivots are inside the box, are removed unless pre-existing, fitted or exact tracked merchant stock. Native MP despawn publication is reused for already tracked extras. There is no global Instantiate hook, ongoing loot sweep, new job or saved component.
- Missing PhysicsLock or a saturated 512-collider query logs a skipped audit rather than deleting from incomplete evidence. The guard cannot remove an arbitrary mod's spawn that occurs later, outside the box, without a collider or without the native saved-item/ForBuy identity. This is deliberately a bounded spawn-time check as requested.

The template's engine is a fitted vehicle part, not merchant inventory. Templates normally support Car loot/Truck cargo, and old Coyote_Trader defaults used car-medical (bandage/first-aid loot). Normal MerchantRuntime.Configure already cleared cargo; these additions also protect direct and restored/forced cargo paths. The available local log is standard WW, not evidence of the reporting player's specific free item cause.
